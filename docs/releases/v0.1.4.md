# Bipli Desktop v0.1.4 — brief

Current release: 0.1.3 (spellcheck menu). This brief collects what 0.1.4 carries.

## Links that leave the app (Sam, 2026-09-24)

- Inside the shell, **only app paths on bipli.com load in the window**. Any other URL — another origin, `mailto:`, or a marketing path on our own origin (`/why`, `/features…`, `/pricing`, `/about`, `/contact`, `/download`, `/try`, `/support`, `/rates`, `/legal…`) — opens in the **system browser**; the in-window navigation is denied. `target=_blank` goes the same way.
- Shell code: `will-navigate` + `setWindowOpenHandler` in `src/main.js` (this release). The web app also redirects those paths to `/` inside the shell as a second belt, and its in-app footer points Support at `/help` (in-app, with Back), Download at a new tab, Contact at `mailto:`.

### Consequence to verify

- **Stripe Checkout and the billing portal** are reached by a same-window jump to `checkout.stripe.com` / `billing.stripe.com`. Inside the shell that jump is now another origin, so it opens in the **system browser** and the return URL lands in the browser, not the shell. The shell's Billing page then needs a refresh (or relaunch) to show the new plan. Google sign-in is unaffected (it starts on our origin and follows a server redirect).
- Release: cut the `v0.1.4` tag to run release.yml (signing + notarisation as before).

## Entry behaviour (Sam, 2026-09-24)

- The shell **never shows the marketing site**. Any marketing path (`/why`, `/features…`, `/pricing`, `/about`, `/contact`, `/download`, `/try`) reached inside the shell goes to `/`.
- **No session** (first launch, signed out, session lapsed) → the **welcome sign-in** screen: the login form with one line above it, "Welcome to Bipli on your desktop. Sign in to get started." After sign-in the app lands on **Home**.
- **Session present** → straight to **Home**.

### Where it lives

Implemented in the web app (Bipli main, 2026-09-24), keyed on the shell detection the web already has (`window.bipliDesktop` bridge, or the `BipliDesktop/` user-agent suffix set by `src/main.js`). The shell keeps loading `BIPLI_URL` (`https://bipli.com`) as it does today; the web decides what that renders. Nothing in the shell needs to change for this, so any 0.1.x shell gets the behaviour the moment bipli.com is republished.
